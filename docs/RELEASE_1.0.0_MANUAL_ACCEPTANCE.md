# Ручная приёмка ACKB 1.0.0 по ролям

Этот документ — исполняемый контрольный список этапа 21. Проверки выполняются на отдельном
приёмочном окружении, а не на рабочей базе колледжа. Пароли, session cookie, CSRF token и
скриншоты с секретами в документ и issue tracker не добавляются.

## Прямые обращения к защищённому API

Проверять в DevTools Console того же origin. Значение CSRF берётся из cookie автоматически и
никуда не копируется:

```javascript
const csrf = decodeURIComponent(
  document.cookie.split("; ").find((item) => item.startsWith("ackb_csrf="))?.split("=")[1] ?? "",
);
const call = (path, method = "GET", body) => fetch(path, {
  method,
  credentials: "include",
  headers: {
    "Accept": "application/json",
    ...(body === undefined ? {} : {
      "Content-Type": "application/json",
      "X-CSRF-Token": csrf,
    }),
  },
  body: body === undefined ? undefined : JSON.stringify(body),
}).then(async (response) => ({
  status: response.status,
  body: await response.json(),
}));
```

Подставлять только UUID приёмочных данных:

- [ ] `API-01` Без session вызвать `GET /api/v1/catalog/components`. Ожидается `401` и
  `authentication_required`.
- [ ] `API-02` Как student вызвать `POST /api/v1/catalog/components/{uuid}/correction-proposals`
  с корректным CSRF и текстом. Ожидается `403 permission_denied`.
- [ ] `API-03` Как teacher вызвать тот же POST. Ожидается `201 open`; затем вызвать
  `PUT /api/v1/workspace/components/{uuid}`. Ожидается `403 permission_denied`.
- [ ] `API-04` Как editor вызвать `GET /api/v1/admin/users`,
  `GET /api/v1/admin/audit-events`, `GET /api/v1/admin/jobs` и
  `POST /api/v1/workspace/components/{uuid}/publish`. Ожидается `403` для каждого.
- [ ] `API-05` Как editor вызвать GET proposal/history для чужой карточки. Ожидается одинаковый
  `404` для чужого и несуществующего UUID, без подтверждения существования объекта.
- [ ] `API-06` Как administrator повторить разрешённую mutation без `X-CSRF-Token`.
  Ожидается `403 csrf_validation_failed` и отсутствие изменения.
- [ ] `API-07` После истечения editor grant вызвать `/api/v1/auth/me`. Ожидается базовая роль
  без editor permission; workspace mutation даёт `403`.
- [ ] `API-08` Проверить error envelope отказов. Ожидаются только `error.code`, русское
  `error.message`, `retryable`, безопасный `request_id`; нет traceback, SQL, Redis/MinIO URL.
