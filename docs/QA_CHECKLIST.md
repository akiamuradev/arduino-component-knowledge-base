# Чек-лист ручной приёмки

Проверяйте релиз в отдельном стенде с тестовыми данными. Не сохраняйте в отчёте пароли,
cookies, CSRF-токены, внутренние URL и скриншоты с секретами.

## Паспорт проверки

- дата, проверяющий и адрес стенда;
- версия и commit SHA из раздела «О системе»;
- браузер, ОС и размеры окна, включая 320 px;
- ссылка на CI и номера найденных дефектов.

Пункт считается пройденным только при ожидаемом результате. Отклонение фиксируется как дефект и
проверяется повторно после исправления.

## Доступ и интерфейс

- [ ] Неверный пароль даёт одинаковое русское сообщение без раскрытия существования пользователя.
- [ ] Student, teacher, editor и administrator входят в отдельных браузерных профилях; роль в
  форме входа не выбирается.
- [ ] После выхода защищённые страницы требуют повторного входа.
- [ ] Светлая, тёмная и системная темы сохраняются после перезагрузки.
- [ ] Интерфейс управляется с клавиатуры, фокус видим, на ширине 320 px нет горизонтального
  переполнения и перекрытых действий.

## Роли

- [ ] Student видит только опубликованный каталог и не видит draft, teacher notes или
  административные действия.
- [ ] Teacher может отправить предложение исправления, но не может редактировать карточку.
- [ ] Editor видит только свои карточки и загрузки, не управляет пользователями, аудитом,
  публикацией и дубликатами.
- [ ] Administrator управляет пользователями и временными editor grants; последний активный
  administrator не может быть отключён.
- [ ] После истечения editor grant редакционные permissions исчезают, а история сохраняется.

## Карточки и медиа

- [ ] Неполный ручной draft сохраняется без обязательного заполнения всех полей.
- [ ] Изображения загружаются и показываются до первого сохранения draft, затем прикрепляются к
  созданной карточке.
- [ ] Недопустимый файл отклоняется без потери формы и ранее загруженных изображений.
- [ ] Готовая карточка проходит `draft → in_review → approved → published`; запрос изменений,
  скрытие, архивирование и восстановление обратимы.
- [ ] Опубликованная карточка использует immutable snapshot и ровно одно основное изображение.

## Импорт и диагностика

- [ ] Allowlisted repository preview показывает revision, лицензию, provenance и предупреждения
  до создания задания.
- [ ] Импорт создаёт только draft; повтор с тем же idempotency key не создаёт дубликат.
- [ ] Editor может отменить или повторить только собственное задание; administrator видит общий
  монитор и безопасную диагностику.
- [ ] Ошибки не содержат traceback, SQL, credentials, внутренних Redis/MinIO URL или исходного
  содержимого parser.

## Защищённый API

- [ ] Запрос каталога без session возвращает `401 authentication_required`.
- [ ] Student и teacher получают `403` на workspace/admin mutations; editor — на publish,
  users, audit и duplicate merge.
- [ ] Mutation без CSRF возвращает `403 csrf_validation_failed` и не меняет состояние.
- [ ] Чужой и несуществующий media/import UUID дают одинаковый `404`.
- [ ] Error envelope содержит только `code`, русское `message`, `retryable` и `request_id`.

## Инфраструктура и итог

- [ ] `/health` и `/ready` отвечают успешно; наружу опубликован только reverse proxy.
- [ ] Backup PostgreSQL и MinIO создан согласованно, checksum проверен, restore выполнен на
  изолированном стенде.
- [ ] Все обязательные CI jobs успешны, открытых блокирующих security alerts нет.
- [ ] Для каждого дефекта есть решение или явный отказ от релиза.
